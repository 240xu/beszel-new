# beszel-new

**beszel-new** 是 [Beszel](https://github.com/henrygd/beszel) 的一个 fork，为 **Panasonic CFQV8-1** 这台 NAS 增加上游没有的硬件采集与风扇控制能力：扩展硬件指标采集（CPU 频率与调频策略、NVMe 健康、WiFi、ACPI/DPTF 热区、风扇状态）、读取 pfanel 曲线历史，以及带完整护栏的风扇档位写入与温控曲线编辑。

它只适用于 Panasonic CFQV8-1。本项目不做通用化，也不承诺其他机型可用。

## 硬件前提：仅 Panasonic CFQV8-1

以下前提全部来自本机实测，是这个项目能成立的前提，也是它的边界。**��机器这套假设大概率不成立。**

- **风扇没有真实转速传感器。** 固件上报的 `fan_speed_rpm` 是哨兵值 `0xFFFFFFFF`，不是转速。因此本项目里所有 rpm 数值都是**估算值**，来源是占空比与固件阶梯表的插值。界面上凡涉及转速的地方都带估算标注，数据结构里用 `rpm_est` / `rpm_est_is_estimate` 明确区分估算与实测。
- **风扇阶梯表来自 ACPI `_FPS`**，读取路径是 `INT3404:00/state*`（注意只认 `INT3404:00`，本机同时发布的 `INT3404:01` 是干扰项）。可写入的档位是**封闭白名单**，定义在 `agent/plus/levels.go`：`{0, 25, 30, 40, 50, 60, 70, 80, 85, 90, 95, 100}`。**`0` 表示交还给固件曲线（auto），不是「关闭风扇」** ��— 显示层把 `0` 渲染成 `auto` 而不是 `0%`，就是为了避免这个误读。
- **EC 路径必须现场探测，不能照抄文档。** `THERMAL_ZONE` 是热区温度文件的**完整路径**，不是热区名字；`EC_ROOT` 与 `FAN_DEVICE` 是两个**互相独立**的配置键，谁也不能从谁推导出来。把这两点搞错的表现是：要么读不到，要么读到别人的数据。

## ⚠️ 安全警告：本项目会改变物理风扇转速

**这不是一个纯粹的只读监控工具。启用风扇写入能力后，你的每一次档位写入都会实际改变这台机器的物理散热行为。** 在你理解下面每一条之前，请不要开启它。

已实现的护栏：

- **写档位需要 admin 权限，并且必须显式 `confirm`。** 没有确认意图的请求会被拒绝。
- **`pfand` 守护进程运行时，手动档位会被拒绝。** 守护进程持有风扇控制权时，人为接管不会被放行——避免两套控制逻辑互相踩。
- **包温达到紧急边界时拒绝写入。** 紧急边界取自温控曲线自身的 `EMERG` 值，不是写死的常数。越热越不许手动降速。
- **写入失败有熔断与回滚。** 连续写入失败达到阈值即触发熔断；在熔断冷却期内控制路径只放行一次探测写入；已经写下去但���被守护进程接管的档位会被回滚，不会把风扇留在一个无人看管的状态。
- **手动档位是临时的。** 到期后自动回归曲线，避免「设了一次就忘了」的长期失控。

即使有这些护栏，它们也是 AI 生成并由测试覆盖的，不是经过现场验证的安全关键件。请自行评估风险。

## 已知限制

诚实列出，包括对我们不利的部分：

- **渲染层用的是源码护栏测试，不是真渲染测试。** 前端工具链缺少 `babel-plugin-macros`，无法在测试里直接渲染带宏的组件，所以部分组件的正确性由「源码结构断言」保证，而非「渲染结果断言」。这类护栏能防住结构漂移，防不住运行时行为。
- **档位候选列表是跨语言镜像。** 前端的档位候选与后端白名单是两份独立维护的副本，靠防漂移测试保证一致。这是妥协：正确的解法是让后端暴露一个端点、前端从接口取。白名单本身在 `agent/plus/levels.go`，改动它时务必让防漂移测试一起变红。
- **降采样记录里扩展指标为空。** 120m / 480m 这些降采样周期的记录，其 plus 数据是空的 —— 上游的聚合器不会累加 plus 分段。这意味着**看长期趋势图时扩展指标会断档**，不是「没数据」，是聚合器根本没算。
- **任何 admin 账号都能停掉风扇守护进程。** 信任域在这里已经从「管理账号」扩大到了「控制物理散热」。这是���个真实的安���边界问题，当前没���更细的权限划分来兜底。
- **翻译只完成了一部分。** 扩展指标的界面文案没有提交过任何一条新翻译，中文界面下很可能看到英文原文。这是已知缺口，不是配置问题。
- **仓库里保留了 AI 开发的全部过程痕迹。** 任务计划、审计报告、修复报告等过程文档都在（虽被 `.gitignore` 排除、不随仓库分发），它们记录了每一次审计否决与返工。想了解某个设计为什么长成这样，去看对应的审计报告。
